# Subsystems

Per-subsystem detail behind the [Architecture](architecture) overview: how
remote execution, SA collection, Sliver C2, credential harvesting, script
delivery, and the test-harness seams actually work. Runtime knobs for all of
these are in [Configuration](configuration).

## NXC execution

**Batched execution** (`netexec/batch_protocol.py`): Both IOC checks and SA collection run one NXC op per box per cycle. Combined scripts use `###C3R_SECTION:name###` / `###C3R_SECTION_END###` delimiters. `split_sections()` handles CLIXML-wrapped Windows output automatically. On Windows, IOC scripts run in isolated runspaces (`[RunspaceFactory]::CreateRunspace()`) — `exit` terminates runspace pipeline without killing host process (~100ms/IOC vs ~5–8s for `Start-Job` over WMI). Runspaces start with no auto-loaded modules, so any check/persistence script using `ScheduledTasks`, `NetSecurity`, or other RSAT modules **must** call `Import-Module <name> -ErrorAction Stop` inside its `try` block — else cmdlet-not-found in runspace yields empty stdout (no JSON, no `-1` fallback) and section parses as `-1` with empty raw content.

**Windows IOC delivery** (`run_nxc_box_check`): Combined PS wrapper uploaded to `C:\Windows\Temp\c3r_<uuid>.ps1` via `put_file` and executed with `powershell.exe -ExecutionPolicy Bypass -File <path>`. Script self-cleans via `Remove-Item $PSCommandPath`. Avoids wmiexec cmd.exe `/c` ~8191 char limit. Wrapper content depends on `SCRIPT_SERVER_URL`:
- **Set**: each runspace fetches its individual IOC script at runtime via `WebClient.DownloadString` with HMAC bearer token bound to `(box_ip, path, exp)` — individual script contents never touch box; URL path = 16-hex hash that leaks no IOC name.
- **Unset (base64 fallback)**: individual IOC scripts base64-encoded and embedded inline in wrapper.

**Linux/firewall IOC delivery**: combined script passed directly to SSH inline — no file upload. Linux uses `#!/bin/bash`; pfSense (FreeBSD) uses `#!/bin/sh` (POSIX-compatible — `/bin/sh` on FreeBSD no support `<(...)` process substitution).

**NXC exec method** (`NXCWrapper.execute()`): accepts optional `exec_method: str | None = None`. When set and `protocol == "smb"`, passes `--exec-method {exec_method}` to nxc. If call fails with smbexec-pattern error (detected by `_EXEC_FAILURE_RE`), retries once without `--exec-method`. C2 exec route passes `exec_method="smbexec"` for SMB targets; SA collection and IOC checks do **not** (they use NXC default).

**Cred-aware wrappers** (`NXCWrapper.execute_cred` / `put_file_cred`): branch on `cred.cred_type`:
- `password`: `nxc smb <ip> -u <u> -p <pw>` (legacy path)
- `nthash`: `nxc smb <ip> -u <u> -H <hash>` with `-d <domain>` when set, else `--local-auth`
- `ccache`: writes ccache blob to `<NXC_PATH>/ccache/<cred_id>.ccache` (chmod 600), sets `KRB5CCNAME=<path>` env on subprocess, passes `-k --use-kcache`. Materialized file reused across calls until `ticket_expires_at` advances (cache key).

**SMB→WinRM→SSH file-delivery fallback** (`netexec/alt_delivery.py`, `docs/PLAN_windows_delivery_fallback.md`): when an SMB `put_file` to a Windows box exhausts its retries with a transient NETBIOS-timeout-class failure (`_TRANSIENT_PUT_RE`), the **file push** (not exec) escalates one tier up — WinRM (`winrm.Session` NTLM on 5985; a plaintext **password** cred, or an **nthash** via pass-the-hash — `_winrm_auth_secret` hands pywinrm an `LM:NT` secret, gated by `NXC_WINRM_ALLOW_PTH`) then SSH (`nxc ssh put_file`, only when `nxc_routing.has_ssh_port(box_ip, db)` sees TCP/22 in the latest nmap SA row). `try_alt_delivery(...)` returns `(NXCResult, method)` for the first tier that lands the file; `NXCResult.delivery_method` (+ `progress_json[ip].exec_path`) records `smb`/`winrm`/`ssh`. Hooked into `NXCWrapper.put_file_cred` (`_maybe_alt_deliver`, gated on the transient regex) and `routes/c2.py::_deploy_one_implant` (`_alt_deliver_and_launch` after all SMB drop-dir candidates fail — opens its own short-lived DB session for the port lookup, safe under `asyncio.gather`). `NXC_ALT_DELIVERY_ENABLED=false` → SMB-only. `alt_delivery.py` is whole-file A7-exempt (alternate-delivery adapter, like `wrapper.py`). **Pass-the-hash (DONE):** an nthash cred drives the WinRM tier via an `LM:NT` PtH secret (requests-ntlm/pyspnego) — the only viable tier for an nthash-only Windows box (SSH can't NTLM-PtH); `NXC_WINRM_ALLOW_PTH=false` reverts to nthash→skip-WinRM.

**WinRM delivery mechanism — server-pull (primary) vs base64 (fallback):** base64-over-WinRM is impractical for real implants (pywinrm wraps each `run_ps` in `powershell -EncodedCommand`, so the whole payload in one command overflows the command-line limit; chunking a 17 MB file = ~15,000 round-trips). So when `SCRIPT_SERVER_URL` is set, `winrm_put_file` stages the file **bytes** in the wrapper cache (`get_wrapper_cache().register(body=<bytes>, ...)` — `WrapperEntry.body` is now `str | bytes`) and the box **pulls** them in ONE `WebClient.DownloadFile` `run_ps` from a new `GET /scripts/file/<token_id>` endpoint (HMAC bearer bound to `file/<id>` + the box's fetch-source IP, single-use, `application/octet-stream`; same `HMACTokenManager` + IP-binding + eviction as `/scripts/wrapper`). `_stage_file_for_pull` mirrors `build_inline_combined_command`'s register+sign. Base64-chunked push (each chunk a SEPARATE small `run_ps`, `_winrm_upload_sync`) is the fallback when `SCRIPT_SERVER_URL` is unset or the cache is full. The `:4000` script listener (`core/script_listener.py`) runs in the SAME process as the backend, so it serves the staged bytes from the same in-process cache. Live true-E2E test (`test_winrm_serverpull_end_to_end_live`) stands up a `start_script_listener` IN the test process so a direct-call test's cache is the one the box pulls from.

## SA collection

Both Linux and Windows use single combined script per box (`build_combined_sa_script` in `sa_collector.py`). Linux: bash via SSH. Windows: PS passed inline (SA commands are short one-liners, no size issue). SA runs on its own background loop (`sa_collection_loop` in `fastapi_backend/lifespan_helpers.py`) separate from IOC checks. Individual-box SA can be triggered on demand via `POST /c2/sa/{box_ip}/collect` ("Run SA Now" button in SA page detail panel).

SA loop runs **first cycle immediately at boot** and every `SA_COLLECTION_INTERVAL_MINUTES` thereafter — competition state no gate it. `db_writer_manager` subprocess started in `_initialize_executor()` (orchestrator boot) via `executor.start_db_writer()`, **not** at competition start, so SA results from both periodic loop and per-box trigger persisted whether or not operator hit START. Stopped on orchestrator shutdown.

`POST /c2/sa/{ip}/collect` **coalesces concurrent triggers per `box_ip`** via `_sa_in_flight: dict[str, asyncio.Future]` table in `routes/c2.py` — two operators clicking "Run SA Now" on same box at same instant share one NXC subprocess + one DB write batch; both receive identical responses (or identical exceptions). Per-box scoping: triggers on different IPs run in parallel without interference.

**Access-loss early-warning alerts** (`docs/PLAN_sa_access_loss_gaps.md`): after each box's SA cycle, `_emit_access_loss_alerts()` (in `sa_collector.py`, called from `_collect_one_box` alongside the `sshguard_block` block) transition-tracks five ways a blue team can sever our access and emits a `warn` alert on the edge *into* the bad state (module-level in-memory trackers, single-asyncio-task model — same as `_sshguard_blocked_boxes`). Kinds: `fail2ban_block` (new `fail2ban` collector — `fail2ban-client status sshd`), `firewall_c2_block` (parses the existing `firewall_rules` category; the Linux collector now also emits an `=NFT=` `nft list ruleset` section, and the monitored port set comes from `_c2_ports_to_check(db)` = config MTLS/script listeners + `PIVOT_LISTENER_PORT_BASE + team_num` per active `PivotSessions` row), `selinux_enforcing` (delta-tracks `mac_status.selinux_mode`), `sshd_config_restricted` (new `sshd_config` collector), `auth_keys_removed` (delta-tracks the additive `auth_keys.keys` fingerprint set). fail2ban/sshd_config are Linux-distro-only (not pfSense/FreeBSD); firewall_c2_block covers Linux + pfSense (Windows is a non-goal). Recovery clears the tracker silently — no transition-out alert.

## Sliver C2

**Event subscriptions** (`c2/sliver_manager.py`): `_handle_events()` subscribes to `session-connected`, `session-disconnected`, `beacon-registered`, `beacon-taskresult`, `beacon-disconnected`. `C2Layout.tsx` listens on same SSE events and calls `queryClient.invalidateQueries` to refresh sessions/beacons immediately rather than waiting for 10-second poll cycle.

**Auto-registration of SliverCheck IOCs** (`_auto_register_implant` in `c2/sliver_manager.py`): fires on every `session-connected` and `beacon-registered` event for non-firewall boxes. Looks up the `ImplantBuilds` row via `implant_identifier` on the connecting session/beacon, then upserts a `DeployedIOCs` row with `source='auto'`, `persistence_mechanism` copied from `ImplantBuilds.persistence_mechanism`. Idempotent: if a row for `(box_ip, ioc_name)` already exists with `status='lost'`, it is reactivated (status → `'active'`); if `status='active'` already, no change. Organic disconnects (no `PendingKills` entry) leave the `DeployedIOCs` row `active` — the check pipeline self-corrects on the next cycle. Intentional kills (`POST /c2/sessions/{id}/kill`, `POST /c2/beacons/{id}/kill`) insert a `PendingKills` row before the gRPC call; `_handle_implant_disconnect()` consumes that row and flips `source='auto'` rows to `status='lost'`. Manual `source='manual'` rows are never touched by auto-registration or kill tracking.

**Implant generation (async)**: `POST /c2/implants/generate` returns `202 {task_id}` immediately; actual Sliver gRPC compile runs in `_bg_generate()` via `fire_and_forget()`. Inside `_bg_generate`, compile is serialised through `_serialized_sliver_compile()` (module-level `asyncio.Lock`) so only one compile runs at a time — concurrent operators queue inside that lock rather than racing Sliver gRPC. Once the build is on disk, `update_task_metadata(task_id, {"build_id": ..., "filename": ...})` is called **before** the DB INSERT so callers polling `GET /c2/tasks/{task_id}` can retrieve the `build_id` even if the INSERT fails (e.g., UNIQUE constraint from a prior run). NXC fanout and DB insert are concurrency-safe and run outside the lock. Poll task status to detect completion; `metadata_json.build_id` is the resolved implant UUID.

**Stale-Sliver-config validity gate** (`docs/PLAN_stale_sliver_config_validity.md`): a build's mTLS signature key lives in Sliver's own `sliver.db` (`implant_config`), which `clean_stale_implants.sh` (1-day threshold) and Sliver restarts prune independently of the backend `implant_builds` DB row and the on-disk `./implants/<uuid>/` binary. When they desync, the surviving row points at a **dead-on-arrival** binary Sliver rejects with `Stream read error [mtls] unknown implant signature key` — a callback flood that reads as "deployed but never called back". The oracle for validity is Sliver's live `client.implant_builds()` list (filename-**stem** membership; Sliver returns stems), wrapped once in `_sliver_known_build_names()` (`routes/c2.py`, **fail-open**: `None` when Sliver is down / `DEV_MODE`, so a transient gRPC blip never bricks deploys). Four sites consume it: (1) **`POST /c2/implants/{id}/deploy`** rejects a stem absent from the live list with `409 {code:"stale_sliver_config"}` *before* any NXC staging — the load-bearing backstop for every caller (UI, `deploy_all`, live tests); (2) **`GET /c2/implants/builds`** annotates each row `sliver_valid`; (3) the **generate `409 Duplicate build`** check skips a Sliver-invalid existing row (compiles fresh instead of offering a DOA "use existing"); (4) the live-test helper `_ensure_build` (`tests/live_session_helper.py`) filters reuse on `sliver_valid`. Same stem-membership predicate already gated `_find_matching_build(known_sliver_names=...)` for the generate dedup path.

**Pivot session automation** (`_maybe_setup_pivot` in `c2/sliver_manager.py`): Fires on every `session-connected` event. Checks if connecting IP belongs to `firewall` OS box, then looks for `ImplantBuilds` row with `pivot_gateway=True` for that IP. Because pfSense (FreeBSD) compiles and connects back before Windows/Linux implants finish compiling, `ImplantBuilds` row may not be committed when event fires — method retries up to **30 times with 3-second delays** before giving up. To avoid `DetachedInstanceError`, only plain scalar values (`build_id`, `tcp_pivot_port`, `team_num_for_fallback`) extracted within each retry-loop session; all actual pivot setup (SOCKS5, portfwd, `PivotSessions` row creation) runs in separate fresh session after build row confirmed. Idempotent — any existing `PivotSessions` row for same `(team_num, pfsense_ip)` deleted first.

**Per-team pivot port allocation**: each team's pfSense pivot session binds unique TCP port on `127.0.0.1` to avoid collisions. `POST /c2/implants/generate` (pivot mode) resolves `effective_pivot_port = body.tcp_pivot_port if body.tcp_pivot_port is not None else config.PIVOT_LISTENER_PORT_BASE + team_num` and stores on `ImplantBuilds` row. `_do_setup_pivot` reads `row.tcp_pivot_port`; row carries no explicit port → falls back to same formula using firewall box's `team_num`. With base 9900 + team_num 1..16, ports run 9901–9916. `body.tcp_pivot_port` defaults to `None` in `ImplantGenerateRequest`; frontend sends `null`.

**OS shell WebSocket hub — PTY-backed** (`c2/pty_hub.py`, docs/PLAN_pty_session_shell.md): `PtyHub` = per-session fan-out for `/c2/sessions/{id}/shell`. Owns ONE Sliver `Shell(EnablePTY=true)` tunnel per session for the lifetime of the modal; a real target-side shell child (bash / pwsh / cmd) is spawned once and stays alive so `cd`, env vars, shell functions, subshells, and interactive TUIs (`vim`, `less`, `top`) all persist. Multiple operators may attach simultaneously — stdin bytes from any client stream over one outbound TunnelData, stdout bytes broadcast to every client and appended to a raw-byte ring buffer (64 KB) that late-joiners receive verbatim, terminated by a `{"type":"replay_end"}` control frame. WS protocol: **binary frames** carry raw stdin/stdout bytes; **text frames** carry JSON control (`replay_end`, `session_dead`, `client_count`, `pong`, `resize`). App-level 60 s empty-`TunnelData` keepalive holds Sliver's ~2 min idle tunnel-death timer off (see project_sliver_pivot_2min_tunnel_death.md). Sliver's `ShellReq` on this sliver-py version has no size field, so runtime resize is not supported — the PTY spawns at the implant's default (typically 80×24); client-sent `{"type":"resize"}` frames are peer-rebroadcast for co-op prompt refitting only. Legacy discrete-command `SessionHub` (`c2/session_hub.py`) is retained as a sibling class but no longer wired to any endpoint. Beacons do not surface an OS-shell modal — Sliver beacons cannot hold tunnels.

**Sliver shell hub** (`c2/sliver_hub.py`): Per-session fan-out for `/c2/sessions/{id}/sliver-shell`, mirrors `SessionHub` but uses Sliver text-dispatch protocol. Commands from any client enqueued as `(line, sender_ws)` and dispatched serially via `sliver_shell_dispatch.dispatch()`. Output broadcast to all clients and stored in rolling 200-line history. `client_count` JSON frames sent on join/leave; `exit` disconnects only sender; hub tears down 5 minutes after last client leaves.

**Sliver shell dispatch** (`c2/sliver_shell_dispatch.py`): Maps typed command lines to Sliver gRPC calls. Uses `shlex.split(line, posix=False)` + quote-stripping for Windows paths with backslashes. Commands with dedicated RPCs: `ps`, `ls`, `pwd`, `cat`, `cd`, `whoami`, `ifconfig`, `netstat` (result = `Netstat` object — iterate `.Entries`), `getsystem`, `migrate`, `socks5`, `portfwd`, `upload`, `download`, `execute`, `execute-assembly`, `mv` (uses `sliver_pb2.MvReq`), `current-token-owner` (uses `sliver_pb2.CurrentTokenOwnerReq`). Commands without dedicated RPC (`cp`, `grep`, `mount`, `chmod`, `chown`) fall back to `interact.execute()`. Import path: `from sliver.pb.sliverpb import sliver_pb2` (not `from sliver import sliver_pb2`).

## Credential harvesting (`c2/cred_harvester.py`)

Two background loops run alongside `cred_revalidation_loop` when `CRED_HARVEST_ENABLED=true`:

- **`HashHarvestLoop`** (`HASH_HARVEST_INTERVAL_MINUTES`, default 5): validates existing `cred_type='nthash'` rows and updates `valid`. For every `is_domain_joined=true` Windows box without a valid hash, harvests credentials via NXC using the best available password cred and upserts `Credentials(cred_type='nthash', source='sam_dump'|'lsa_dump')` rows. See `c2/cred_harvester.py` for implementation details.

- **`TicketRefreshLoop`** (`TICKET_REFRESH_INTERVAL_MINUTES`, default 5): for each team whose DC is owned, acquires the krbtgt credential via impacket tooling when `KRBTGT_DCSYNC_ENABLED=true` and stamps the domain SID on all team `Boxes` rows. Then forges a Kerberos ticket for `Administrator` via `forge_golden_ticket()` and stores a team-scoped `Credentials(box_ip=NULL, team_num=N, cred_type='ccache', ccache_blob=<b64>)` row. Refreshes when `ticket_expires_at - now < TICKET_REFRESH_BEFORE_EXPIRY_MIN`. Validates the ticket via NXC to flip `valid`. See `c2/cred_harvester.py` for implementation details.

**Routes** (`routes/c2.py`):
- `POST /c2/harvest/{box_ip}` — operator manual SAM/LSA dump (bypasses loop's `is_domain_joined` filter). Returns ``202 {task_id}`` immediately; background coroutine writes per-box progress + terminal status to ``OperatorTask(task_type='harvest')`` — operators watch it in `/c2/tasks`.
- `POST /c2/forge-ticket` — body `{team_num, principal?, duration_hours?}` — manual golden ticket forge.
- `GET /c2/tickets` — list team-scoped ccache rows + `expires_in_min`.
- `POST /c2/tickets/{id}/refresh` — force re-forge.
- `POST /c2/tickets/{id}/validate` — body `{box_ip?}` — validate the forged ticket via Kerberos domain auth against the team's boxes (or one box). Windows go through `nxc smb -k --use-kcache --kdcHost <dc> --shares`; domain-joined Linux use a real `ssh` GSSAPI login (forging a per-user ticket) with an `impacket-getST host/<fqdn>` fallback — `nxc ssh` cannot do GSSAPI. Returns per-box `{valid, method, detail}`; a whole-team run stamps the ticket row's `valid`. See `docs/PLAN_ticket_multibox_validation.md`.
- `DELETE /c2/tickets/{id}` — revoke + delete materialized ccache file.

**Frontend**: `C2CredsPage.tsx` at `/c2/creds` is tabbed (PASSWORDS / HASHES / TICKETS). The TICKETS tab renders ccache rows from `GET /c2/tickets` with VALIDATE (`ticket-validate-{id}`, per-box results sub-row + single-box picker) / REFRESH (`ticket-refresh-{id}`) / REVOKE (`ticket-revoke-{id}`) per-row actions; FORGE form lives under `[FORGE_TICKET]` (`forge-ticket-btn`). HASHES tab has a `[DUMP_FROM_BOX]` action dispatching async `POST /c2/harvest/{box_ip}` (202 → `task_id`) and surfacing a sonner toast with a VIEW action that opens `/c2/tasks` — concurrent dumps queue cleanly there rather than stacking per-page modals.

**Opsec callouts**: `KRBTGT_DCSYNC_ENABLED` = kill switch for DCSync operations in noise-sensitive environments. ccache blobs in SQLite unencrypted at rest; protect host DB.

## Sliver console PTY (`c2/sliver_console.py`)

Per-operator interactive `sliver-client` terminal via WebSocket. Each WS connection spawns an independent PTY subprocess — no session sharing, no history replay across reconnects.

**Auth**: token in query param `?token=`; blue team or missing token → `ws.close(code=4003)` before accept. Admin and red team allowed.

**Spawn**: `pty.openpty()` → master/slave fds; `asyncio.create_subprocess_exec(SLIVER_CLIENT_BIN, "console", stdin=slave_fd, stdout=slave_fd, stderr=slave_fd)`. `os.close(slave_fd)` after spawn. `sliver-client` has no `--config` flag; it loads the operator config from `~/.sliver-client/configs/` (pre-imported via `sliver-client import <cfg>`). `FileNotFoundError` → error text sent to WS, WS closed cleanly.

**I/O**: two concurrent tasks — `pty_to_ws` reads `master_fd` via `loop.run_in_executor(None, os.read, master_fd, 4096)` (non-blocking), sends decoded text to WS; `ws_to_pty` receives WS text, JSON-parses for control frames first, falls through to `os.write(master_fd, data.encode())`.

**Resize**: JSON control frame `{"type": "resize", "cols": N, "rows": M}` from frontend → `fcntl.ioctl(master_fd, termios.TIOCSWINSZ, struct.pack("HHHH", rows, cols, 0, 0))`. Initial size set to 50×220 at spawn time.

**DEV_MODE**: when `config.DEV_MODE=True`, sends a stub message (`[DEV MODE] Sliver console not available`) and closes — no subprocess spawned.

**Cleanup**: on WS disconnect or I/O error, `master_fd` closed, `proc.terminate()` called, then `proc.wait()` with 3s timeout; if still alive, `proc.kill()`.

**Config**: `SLIVER_CLIENT_BIN` (default `"sliver-client"`) and `SLIVER_CFG_PATH` (default `"./sliver_operator.cfg"`) in `core/config.py`.

## Playbook scheduler (`core/playbook_scheduler.py`)

Executes YAML-defined operator actions at `T+offset` relative to `competition_start_at`.

**Config file**: `config/playbook.yml` (gitignored; `config/playbook.example.yml` committed). Loaded once at server start by `core/playbook_loader.py`. If absent, playbook is a no-op.

**Entry format** (`config/playbook.example.yml`):
```yaml
- at: "00:05:00"          # T+HH:MM:SS from competition start
  action: exec            # exec | deploy | implant | module
  os: windows             # filter: all boxes matching this OS
  command: "whoami"       # for action=exec
  ioc_name: "..."         # for action=implant
```

**Scheduling**: `register_playbook_jobs(competition_start_at)` called when competition transitions to `Running`. Each entry becomes an `asyncio.create_task(...)` entry stored in the module-level `_playbook_tasks: list[asyncio.Task]`; the task `await asyncio.sleep(delay)` until `competition_start_at + timedelta` then fires. No APScheduler involvement. `competition_start_at` is persisted to `CompetitionConfig` DB row (singleton `id=1`) so playbook jobs survive backend restarts — re-registered on startup if `competition_start_at` already set and jobs not yet fired.

**Dispatch**: each fired job fans out to all inventory boxes matching the entry's `os` field. Creates an `OperatorTask` row with `operator='playbook'` and `task_type` matching the action — visible in the Task Queue page.

**Orchestrator surface**: `GET /admin/status` includes `components.playbook.{job_count, entries_loaded}`. `job_count` is the count of currently-registered asyncio playbook tasks (`_playbook_tasks` list in `playbook_scheduler.py`). `cancel_playbook_jobs()` called on competition stop/reset.

## Seeder & e2e

**`PIVOT_TEAM_INDICES`** (`scripts/testing/seed_dummy_data.py`) = `{1, 2, 3}` — controls which teams receive seeded `PivotSessions` rows in dev/test (indices into sorted inventory team list, **not** team_num values). Team index 0 deliberately excluded so `tests/test_e2e_pivot.py` can verify real pivot automation without conflicting with pre-seeded data.

**Pivot e2e test** (`tests/test_e2e_pivot.py`, marker `pivot`): one run per live team (parametrized via a `team_num` fixture over `AVAILABLE_TEAMS`). No longer special-cased in the binding layer — it's just another full-team (`boxset_`) group like every other `_FILE_STEM_FORCE_LIVE` file, see "Box-scoped live-worker binding" below. Requires a running Sliver server; excluded from standard `python tests/run_tests.py` suite unless explicitly requested (`-m pivot`). All 9 original phases (generate pivot set → session checkin → DB rows → internal sessions → pre-firewall exec → apply block → post-firewall exec → sessions still alive → persistence verification) live in one function, `test_pivot_lifecycle`, not 9 separate `@pytest.mark.order()`-marked tests — see the module docstring for why (`pytest-order` clusters same-order-number items across every parametrized team before moving to the next order number, so state can't be threaded through module-level globals the way the original single-team version did).

**Box-scoped live-worker binding** (`docs/PLAN_box_scoped_live_workers.md`) — supersedes the earlier per-(team, role) pool/lock design (`docs/PLAN_live_worker_team_binding.md` §5c/§5d), which computed an indirect **pool number** per live item and resolved it to a real team via `_team_for_pool` — different namespaces (`live_team_*`, `script_team_*`, per-force-live-file `{stem}_team*`, `pivot_team*`) could independently alias onto the *same* real team from different `xdist_group` names, which xdist has no way to detect, so a custom cross-process mutex (`_acquire_team_scope`) had to exist just to catch that aliasing. The replacement removes the indirection instead of patching around it: a group name now directly encodes the real box(es) it claims — `box_<ip>` for a single box, `boxset_<ip>-<ip>-...` (sorted) for a team's whole 5-box set — so two different call sites that mean the same real box always produce the byte-identical group string, and `--dist=loadgroup`'s own "all items in group X land on one worker" guarantee is sufficient on its own. No custom lock exists anymore.
  - **Single-box** (matrix/pool-injection/backup-copy/resilient-iocs, i.e. everything NOT in `_FILE_STEM_FORCE_LIVE`): `conftest._box_for_item()` resolves `(team_num, box_ip)` deterministically from a stable sha256 hash of the item's own `nodeid`, spread across **every** live team's matching box (not capped to a subset) — `role` (`firewall`/`windows`/`linux`) comes from `_infer_role()` reading the item's own `box_os`/`os_key` param or an `ioc_name` → OS lookup, same as before; a `windows` role additionally checks the shared `conftest._WORKSTATION_ONLY` set (also imported by `tests/test_e2e_ioc_matrix.py`, so the box a test is locked to and the box its body actually dispatches to can never diverge) to pick the workstation box (index 1) over the DC (index 0). Falls back to the full-team path when the role can't be determined, matching the old "omit role suffix -> full team" safety behavior.
  - **Full-team**: every `_FILE_STEM_FORCE_LIVE` file, `test_e2e_pivot` included, gets `boxset_<that team's 5 box IPs>`. Team comes from pivot's own `team_num` parametrize param when present, else a stable hash of `(file_stem, nodeid)` spread across every `AVAILABLE_TEAMS` entry — no `MAX_SLIVER_WORKERS`-sized cap on team coverage for these files (only the Sliver-concurrency semaphore below still bounds concurrent Sliver-heavy work, independent of team/file identity). Two different full-team files that happen to hash to the same real team automatically land in the identical `boxset_` group — and therefore the same worker, serialized — with no extra coordination code, since box identity *is* the group key.

`_resolve_group()` inverts any group name back to `(team_num, box_ips)` via a `_team_for_box_ip()` reverse lookup against the real inventory. `pytest_runtest_setup` resolves + applies the binding for whichever group the **currently executing** item belongs to, right before it runs (verified empirically: this hook fires before fixture setup) — including reloading that worker's own backend (`POST /admin/reload_inventory`, `#admin`) when the resolved box(es) differ from what it last loaded, and narrowing `CONFIG["targets"]` to just those box(es) via `_apply_targets`. `BOUND_TEAM` still exists as a back-compat module attribute (synced to whichever team is currently bound) for files not yet using per-test resolution.

**Box completion signal** (generalizes the old pivot-specific windows/linux wait into a uniform mechanism every full-team group gets transparently): `conftest` tracks live-item completion keyed by box IP (only single-box items are recorded — a full-team group's own items must never count toward the boxes it's about to wait on, or it would wait on its own completion and never proceed). `pytest_collection_modifyitems` increments a pending counter per single-box item; `pytest_deselected` corrects it for `-k`/`-m` filtering (verified empirically: `pytest_collection_modifyitems`, even `tryfirst=True`, sees the full pre-deselection item list — deselection is a separate, later-running hook); `pytest_runtest_teardown` decrements it and touches a `logs/xdist_workers/box_<ip>.done` marker at zero; `pytest_collection_finish` marks a zero-pending box done immediately (so a box no single-box item ever resolved to doesn't block a full-team group forever) and clears any stale marker left by a prior pytest session for a box with real pending work this run. `pytest_runtest_setup` waits on every one of a full-team group's boxes' markers (bounded, `BOX_WAIT_TIMEOUT` env var, default 3600s) **before** binding — no per-file fixture code needed, `test_e2e_pivot.py`'s `pivot_setup` no longer calls anything special — fails loud on timeout, not a skip.

**Sliver-concurrency semaphore** (`_acquire_sliver_slot`/`_release_sliver_slot`) — replaces the old `force_live_slots`/`sliver_slots` pool-count cap, which tied Sliver-server concurrency directly to team identity (only the first `MAX_SLIVER_WORKERS` teams in `AVAILABLE_TEAMS` ever got Sliver-bound live coverage, in any run). `MAX_SLIVER_WORKERS` (default 10, raised from 6) interchangeable file-based slots (`os.O_CREAT | os.O_EXCL`, mirroring the old lock's primitive) — any Sliver-touching group (i.e. not `script_kind`-only, tracked via `conftest._sliver_groups` populated at collection time) holds one slot for as long as it's bound, released on switching to a non-Sliver group; moving between two Sliver-marked groups keeps the slot rather than release-then-reacquire. This rotates real coverage across every live team instead of hard-partitioning to a fixed subset. `pytest_configure` sweeps stale `sliver_slot_*.lock` files left by a killed/crashed prior run.

## Unified script wrapper (`netexec/script_wrapper.py`)

Single source of truth for NXC script delivery — three entry points front every `nxc.execute` / `nxc.put_file` call that delivers a script body to a target box.

**API**:
- `build_inline_command(script_path, box_os, server_url=None, auth_token=None, box_ip=None)` — thin loader for a single static IOC script. Fetches via `/scripts/<hash>` (Windows `WebClient.DownloadString` | Linux `curl`). Falls back to base64 inline when `server_url` is unset.
- `build_inline_combined_command(combined_body, box_os, box_ip, *, expires_in_sec=None)` — registers a dynamic body in the in-memory `WrapperCache` and returns a tiny bootstrap (~600-1500 bytes regardless of body size) the target fetches via `/scripts/wrapper/<token_id>`. Replaces put_file on Windows (no disk artifact) and inline-SSH on Linux/pfSense (no process-tree leak). Raises `WrapperCacheFullError` when the cache is at capacity OR `SCRIPT_SERVER_URL` is unset — callers fall back to legacy delivery for that single call (do NOT flip the global `USE_SCRIPT_WRAPPER` flag).
- `build_inline_raw_command(cmd, box_os)` — process-line obfuscation for short single-line commands. Windows wraps in `powershell.exe -EncodedCommand <b64>`; Linux/pfSense passes through (SSH-stdin delivery keeps the body off the target's command line).

**Cache lifecycle**: `WrapperCache` is a module-level singleton via `get_wrapper_cache()`. TTL-only eviction with a hard size cap (`SCRIPT_WRAPPER_MAX_CACHE_ENTRIES`, default 1024). `WrapperCacheFullError` raised when register is called at capacity. Three eviction paths:
1. **Single-use** — `fetch()` evicts entry on first successful read (one body served once).
2. **Lazy on read** — expired entries evicted when fetch sees `expiry_unix <= now`.
3. **Periodic sweep** — `wrapper_cache_sweep_loop()` background task (spawned in `lifespan_helpers.register_background_loops`) evicts expired entries every `SCRIPT_WRAPPER_SWEEP_INTERVAL_SEC` (default 30s).

**Shutdown**: `lifespan_helpers.teardown` calls `get_wrapper_cache().clear()` to release plaintext bodies from memory before process exit.

**Fallback chain**: bootstrap on Linux/pfSense uses `(curl -sk ... || wget -qO- ...)` so minimal images without curl still fetch. Final tier (both curl and wget absent) requires the caller to fall back to legacy base64-inline delivery — surface via `WrapperCacheFullError`-caught path; `app.state.box_fetch_method` cache for sticky per-box decisions is a follow-up.

**`GET /scripts/wrapper/<token_id>` endpoint** (`routes/scripts.py`): HMAC bearer token via `HMACTokenManager` binds `(client_ip, "wrapper/<id>", exp_unix)`. Mismatched IP → 403; expired/missing → 404; invalid signature → 401. Single-use eviction. The bound `client_ip` is the box's **fetch-source** IP: `build_inline_command`/`build_inline_combined_command` set `bind_ip = fetch_client_ip or _wan_ip_for(box_ip) or box_ip`, so a firewall that fetches from its `wan_ip` gets a token that validates from its WAN (binding to the LAN `box_ip` → 401 → "No output from nxc"). See `docs/PLAN_firewall_wan_lan.md`.

**Security caveat**: wrapper cache holds **plaintext script bodies in memory**. Anyone with a backend memory dump (gdb, core file, ptrace) can read them. Acceptable in the current trust model (backend host is admin-controlled). Same caveat applies to `ccache_blob` rows in SQLite — no new attack surface introduced.

**A7 audit fence** (`scripts/audit/run_audit.sh`): scans `fastapi_backend/` for `nxc.execute` / `nxc.put_file` call sites that do not route through `script_wrapper.py`. Exemptions are tagged with `# nxc-wrapper-bypass: <reason>` on the call line (reasons: `wrapper-delivered`, `binary-deploy`, `legacy-rollback`, `immutable-apply`, `operator-module`, `cred-validation`, `internal-adapter`). **Hard gate:** any untagged hit fails the audit (exit 1) — an untagged site is a potential IOC-script disk/cmdline leak. `module_runner.py` is whole-file exempt (operator-supplied modules, not IOC scoring scripts), alongside `wrapper.py`, `script_wrapper.py`, `cred_harvester.py`, `nxc_routing.py`.

**Section-name obfuscation** (`batch_protocol.section_token`): IOC check/deploy/remediate combined scripts emit `###C3R_SECTION:<token>###` markers where `token = HMAC_SHA256(SCRIPT_HMAC_SECRET, "c3r-section:" + logical_name)[:16]` — so the raw IOC name (`wmi_event_subscription`) never appears in the body even if it lands on disk/cmdline/debug-log. Producers (`check_runner`, `deploy_manager`) and consumers both call `section_token`; `split_sections` is name-agnostic so SA-collection markers keep their raw category names.

**Recorded-dir injection + per-row section keying** (`docs/PLAN_recorded_deploy_dirs.md`): the `logical_name` fed to `section_token` is `_section_name(ioc_name, deployed_ioc_id)` = `f"{ioc_name}#{did}"` (effect) / `…#{did}__persistence`, or the bare `ioc_name` when `did is None` (deploy of an unregistered IOC, single instance). This makes two active `DeployedIOCs` rows for the same IOC at *different* pool dirs emit two **distinct** section tokens — the consumer builds `{section_token(_section_name(t.ioc_name, t.deployed_ioc_id)): t}` and routes each parsed section back to its `deployed_ioc_id` by token (never by string-splitting the name). Before each section's fetch/`AddScript`, `c2/deploy_params.params_env_prefix(row.deploy_params, box_os)` prepends that row's recorded `C3R_<KEY>` env vars (Linux/pfSense `KEY='v'; export KEY;` inside the subshell; Windows `$env:KEY='v'` before the runspace — visible inside it). The SAME emitter runs on deploy (`deploy_manager._build_combined_script` / `routes/ioc_deploy._deploy_one`), check (`check_runner._build_combined_ioc_{linux,windows}`), and remediate. `IOCTask.deploy_params` carries the parsed dict from `check_manager` (`d.params_dict` at task build). A successful RED remediate of a row flips it to `status='failed'` (`deploy_manager._mark_rows_failed`). The **add-location** dir pick lives in one seam — `deploy_params.resolve_deploy_params(ioc, box_os, exclude_dirs=existing_active_dirs)` → `pick_unused_deploy_path` (pool minus already-used dirs; `None` when exhausted → per-box skip). Maintenance re-runs (soak/deploy_manager, `beacon_watcher` via `_recorded_deploy_dir`) **reuse** the recorded dir, never pick a new one.

**Artifact NAME pools + BUILD/CHECK (`docs/PLAN_build_check_deploy_name_pools.md`):** `resolve_deploy_params` also picks pooled NAMES — for each `(env_key, kind)` in `IOC.pooled_names`, `naming_pools.pick_unused_name(kind, os, difficulty, exclude)` (tiered, from `config/naming_pools.yml` `name_pools:`, distinct-on-redeploy via `existing_active_names`) → added to `deploy_params` as `env_key` → injected `C3R_<env_key>` → the converted deploy/check/remediate read `${C3R_<env_key>:-<old>}`. `resolve_protect_paths(paths, params)` templates persistence immutability targets from the recorded params. The admin **BUILD** step (`core/build_all.run_build_all`) compiles implants build-only (reuse-recent via `_find_matching_build`, or `force`) and recompiles coupled shims via `c2/shim_builder.build_shim(ioc, defines)` — mirrors each `scripts/build/build_*.sh` toolchain, passes pool-driven `-D<KEY>="<v>"` into the `#ifndef`-guarded sources, caches by `(source_sha256, defines)` in `SHIM_CACHE_DIR`, records `c2/build_manifest.py` (path→{defines, source_sha256}). **CHECK** (`core/build_check`) reads the manifest to classify each IOC present/missing/stale; **DEPLOY-ALL** (`deploy_all._do_implant`) gates on `_find_matching_build` so it never inline-compiles. `shim_builder` fails loud on a missing toolchain (`ShimToolchainError`) — never ships a stale-path shim to a moved artifact.

**Disk-fallback gate** (`ALLOW_DISK_SCRIPT_FALLBACK`, default `false`): `check_runner.run_nxc_box_check` and `deploy_manager._run_box_action` deliver the combined body via the wrapper cache first; on `WrapperCacheFullError` (cache full / wrapper off / `SCRIPT_SERVER_URL` unset) the **Windows** branch disk-drops a `.ps1` only when this flag is true, else it fails the box's IOCs loud. The **Linux/pfSense** branch falls back to inline-SSH (no disk artifact) and is never gated.

**Result callback** (`netexec/script_result.py`, docs/PLAN_script_result_callback.md) — closes a proven live-VM bug: NXC's smbexec/wmiexec output readback (`get_output_remote()` in impacket) has no completion check on the remote process — it reads the redirected-stdout file as soon as it can open it, and cmd.exe's `>` redirect creates that file empty at process start, so an early read can succeed with zero/partial bytes and no error, silently losing a result the script actually produced (confirmed live: the deploy always succeeded on the target, only NXC's report of it was lost). Both `build_inline_command` and `build_inline_combined_command` now — when `USE_SCRIPT_RESULT_CALLBACK` is on (default `true`) — capture the script's output (Windows: an isolated `[RunspaceFactory]::CreateRunspace()`, the same exit-survival pattern the combined-script sections already use, since a bare `iex` would let the script's own `exit` kill the bootstrap before it could POST; Linux/pfSense: `$(...)` command substitution, a subshell for the same reason) and `POST` it to `POST /scripts/wrapper/<token_id>/result` (`routes/scripts.py`) before also re-emitting it to the bootstrap's own output stream, so NXC's own readback keeps working as the documented fallback.

`netexec/script_result.ResultRegistry` (module-level singleton via `get_result_registry()`) holds one pending entry per token, created by `register()` (called synchronously — no event loop required, since builder functions are sometimes invoked from sync test code — the actual `asyncio.Event` a real wait blocks on is created lazily inside `wait()`, which is always awaited) before the wrapper functions hand back the bootstrap. `resolve()` (called by the POST handler) sets it; `wait(token_id, timeout)` blocks up to `SCRIPT_RESULT_GRACE_SEC` (default 5s — intentionally short, not a fresh timeout, since the dispatching NXC call has already spent real wall-clock time internally by the time callers start this wait) and always discards the entry whether resolved or timed out (no leaked pending futures). `await_callback_result(cmd, fallback_output)` is the shared call-site helper (used by `check_runner.py`'s `_run_check`/`run_nxc_box_check`, `deploy_manager.py`'s `_run_box_action`, `routes/ioc_deploy.py`'s `_deploy_one`) — prefers the POSTed result, falls back to NXC's own output unchanged when the callback never fires (disabled, no `box_ip` to scope a token, or timeout) — purely additive, never worse than pre-callback behavior.

Per-section fetches embedded *inside* a combined script (`check_runner._emit_linux_section`) pass `enable_result_callback=False` — the outer combined bootstrap already owns the whole script's result callback; each section independently POSTing its own partial result would be wrong. SA collection (`c2/sa_collector.py`) shares the same bootstrap-building functions and picks up the capture-then-POST bootstrap shape, but is explicitly out of scope for the consumption/await side — its existing NXC-based reads keep working unaffected since the bootstrap still re-emits to its natural output stream.

## Bulk exec async (`c2/bulk_exec.py`)

`POST /c2/bulk/exec/async` accepts `target_boxes`, `command`, `method` (`session`|`beacon`|`nxc`), optional `implant_name`/`cred_type`/`per_box_timeout_sec`/`confirm_missing`. Returns `202 {task_id}` immediately; per-box progress lives on the resulting `OperatorTask` row.

**Concurrency**: module-level `asyncio.Semaphore` pair coordinates fanout across dispatchers — `_bulk_semaphore` capped at `BULK_EXEC_MAX_CONCURRENT`, `_nxc_semaphore` capped at `NXC_MAX_CONCURRENT`. Effective concurrency for `nxc` method is `min(NXC_MAX_CONCURRENT, BULK_EXEC_MAX_CONCURRENT)`. Reset via `reset_bulk_exec_semaphores()` when admin patches either setting.

**Concurrent-submit guard**: `has_running_bulk_exec()` checks the `OperatorTask` table for `task_type='bulk_exec'` rows in `pending`/`running` status. Second submission while one is in flight → `409 {"code":"another_bulk_exec_running"}`.

**Implant resolver**: `resolve_implants_per_box(target_boxes, implant_name, method)` queries the live Sliver client. Missing implants → `409 {"code":"missing_implants", "missing_boxes":[...], "total_boxes":N}` unless `confirm_missing=true` is set on resubmit. Implants are re-resolved at dispatch time too (`_dispatch_session` / `_dispatch_beacon`); a session that dies between resolve and dispatch raises `ImplantDiedAfterResolveError` — distinct from `not-found-at-resolve` so the progress row shows the explicit race condition.

**Beacon poller hook** (plan §2.6): `_dispatch_beacon` registers the issued Sliver task ID in `beacon_task_poller._bulk_exec_beacon_task_map`. When the global beacon poller drains the result, `_consume_bulk_exec_hook(sliver_task_id, content)` pops the entry and calls `update_box_progress(...)` with stdout/stderr/exit_code. Hook + dispatcher's own `asyncio.wait_for(future, ...)` are idempotent — whichever resolves first wins.

**Command quoting**: `split_command(command, box_os)` uses `shlex.split(posix=True)` for Linux/pfSense and `posix=False` for Windows so backslashes in Windows paths are preserved.

**Output decoding**: `decode_stdout(raw, box_os)` tries UTF-8, then cp437 (legacy Windows console), then latin-1 with replacement. Used for both stdout and stderr.

## Timestomping (`c2/timestomp.py`)

Sets file timestamps on artefacts to match a sibling reference in the drop directory so blue-team `find -newer` / `Get-ChildItem | Sort-Object LastWriteTime` heuristics don't flag the artefact.

**Trigger surfaces**:
- `IOC.timestomp=True` (dataclass field on `iocs.base.IOC`) + `IOC.timestomp_paths=[...]` → fired by IOC deploy-and-register (`routes/ioc_deploy.py:_bg_deploy_and_register`).
- Implant Generate-page checkbox → `ImplantGenerateRequest.timestomp=True` → fires `stomp_files_safe` on the deployed binary in `routes/c2.py:_bg_generate`.
- Deployment-page DEPLOY & REGISTER modal checkbox → `IOCDeployAndRegisterRequest.timestomp=True` (operator-level override).
- Sliver-shell `upload --timestomp <local> <remote>` → `c2/sliver_shell_dispatch.py:_post_upload_stomp`.
- Persistence inheritance — when an implant deploys with `timestomp=True` AND the persistence mechanism has `protect_paths`, those paths are stomped after the persistence deploy script runs.

**Ordering** (plan §3.3): stomp MUST run BEFORE any immutable-application step (`chattr +i` / `chflags schg` / `attrib +R`). Once a file is immutable, subsequent `touch`/`debugfs` writes fail with EPERM. The deploy pipeline enforces this — `_apply_persistence_post_deploy` stomps persistence artefacts first, then applies immutability. Implant-binary stomp similarly runs before the binary's own immutability.

**Reference picker** (`pick_reference`): for each unique destination directory, list entries alphabetically (excluding only `.` and `..`; other dotfiles INCLUDED — dotfile-heavy dirs like `~/.ssh`, `/etc/skel` are valid reference sources). Find where the dropped filename would slot lexicographically; pick `listing[i-1]` (preferred) or `listing[i+1]`. Fall back to parent-directory mtime if listing is empty.

**Per-OS mechanism**:
- **Windows**: single PowerShell block per file sets `LastWriteTime`, `CreationTime`, `LastAccessTime` via `Get-Item / Set-ItemProperty`. Wrapped via `build_inline_raw_command` for process-line obfuscation.
- **Linux ext4/btrfs**: `touch -r <ref> <target>` covers mtime + atime; `debugfs -w -R "set_inode_field <inode> crtime ..."` covers btime. Filesystem detected via `df -T`; debugfs presence cached per-box. Unsupported FS (xfs/overlay/tmpfs/nfs) → btime skipped, mtime+atime only — file still counts as success because btime was never claimed.
- **pfSense (FreeBSD UFS2)**: `touch -r` for mtime+atime; Python3 `os.utime(ns=...)` for btime when `/usr/local/bin/python3` exists.

**All-three success semantics**: per-file success requires every requested timestamp attr to land. A file with `mtime=1, atime=1, btime=null` counts as success (btime unsupported on this FS). A file with any attr=0 counts as failure with `partial=True` indicating other attrs may have succeeded.

**Telemetry**: aggregated task-level on `OperatorTask.metadata_json.timestomp` with `attempted`, `succeeded`, `failed[].path/err/partial`, and a `per_box` map. Per-box mirrors live on `OperatorTask.progress_json[ip].details.timestomp` for UI convenience.

**A8 audit fence** (`scripts/audit/run_audit.sh`): scans `iocs/check_scripts/` for timestamp predicates (`LastWriteTime`, `st_mtime`, `-mtime`, etc.) that timestomp would invalidate. Empty baseline today; the fence flags regressions before they ship.

**Sliver disconnect retry**: not implemented in v1 — current path always uses NXC delivery via `execute_cred`. Live-VM follow-up will add session-first attempts with retry.
